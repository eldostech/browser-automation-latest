# The browser. A replay drives Playwright directly: the MCP hop was a Node
# process that then called this library, and it could not offer auto-waiting,
# locator strictness or traces.
#
# Pinned to a minor range because `playwright codegen`'s output is the input
# the recorder parses, and that output is not a stable contract. A golden-file
# test per supported action makes an upgrade that changes it fail in CI rather
# than in somebody's thousand-row batch.
#
# `python -m playwright install chromium` downloads the browser itself; `make
# browsers` does it for you.
playwright>=1.48,<2.0

# The model, for the one thing that still costs tokens: looking at a page when
# a locator breaks. langchain-aws supplies the Bedrock wiring -- endpoints,
# auth, model IDs -- which is the part that rots; langchain-core is the message
# types it speaks. Bedrock is the only provider, deliberately: a second one is
# a second code path to keep working.
#
# What used to be here and is not any more: langgraph, its two checkpoint
# backends, and the MCP client. They served the agent that recorded workflows
# by driving a browser itself. A workflow is recorded by watching a person do
# it now, so there is no loop to orchestrate, no run to checkpoint, and no
# MCP server to talk to.
langchain-core>=1.6,<2.0
langchain-aws>=1.7,<2.0

# botocore, for resolving and reporting AWS credentials in /healthz.
botocore>=1.34,<2.0

# S3 artifact storage (STORAGE_BACKEND=s3). Only imported when that backend is
# selected, so a local-only deployment never pays for it at runtime -- but it
# is a hard dependency rather than an extra, because a missing package
# discovered on the first screenshot of a production run is not a good trade
# for a few megabytes.
boto3>=1.34,<2.0

# Reading input files. pandas, and openpyxl as its Excel engine.
#
# The comment that used to sit here argued *against* pandas -- "this needs cell
# values, not a dataframe, and pandas would pull in numpy for nothing" -- and
# that was right for the job it described, which was reading rows and handing
# them to a browser. It stopped being right when mapping arrived: the mapper
# needs each column described as well as read (type, blanks, distinct count,
# example values), plus delimiter sniffing and encoding fallbacks. Writing that
# by hand is writing pandas badly.
#
# What pandas is deliberately NOT allowed to do is coerce types. Files are read
# with dtype=str and Excel cells converted explicitly, because a reader that
# helpfully turns 0071 into 71 produces a thousand wrong records and no error.
# See ingest.py.
pandas>=2.2,<3.0
openpyxl>=3.1,<4.0

# Comparing two screenshots of the same step. A downscaled per-pixel diff
# answers "did this page change, roughly how much" in a few milliseconds;
# SSIM and friends want numpy and model perceptual similarity, which is a
# better answer to a question nobody here is asking. See imagediff.py.
pillow>=10.0,<12.0

# Postgres via SQLAlchemy 2.0, with Alembic owning the schema.
sqlalchemy[asyncio]>=2.0,<3.0

# The vector column healing memory is built on. The extension lives on the
# PostgreSQL server; this is the SQLAlchemy type that talks to it, and without
# it the models cannot even be imported.
pgvector>=0.3,<0.5

# TWO drivers, for two jobs, and the split is not a matter of taste.
#
# asyncpg runs the application. On Windows, psycopg's async mode requires a
# SelectorEventLoop while asyncio subprocesses require a ProactorEventLoop --
# and this process must do both, because it spawns `npx @playwright/mcp` over
# stdio and queries the database in the same loop. asyncpg works under either.
#
# psycopg runs Alembic, which is synchronous and so never meets that
# constraint. It is also what LangGraph's Postgres checkpointer uses.
# Neither is imported by name anywhere: SQLAlchemy loads them from the driver
# in the URL, which is exactly why they are easy to leave out of this file.
asyncpg>=0.29,<1.0
psycopg[binary,pool]>=3.2,<4.0
